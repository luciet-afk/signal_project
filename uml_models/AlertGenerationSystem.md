The UML represents three main core classes, the AlertGenerator, AlertManager and Alert. Each of these classes is also supported by the objects Patient, Vitals, ThresholdRule and MedicalStaff. Each Patient holds a list of their recorded Vitals, and the assigned acceptable ThresholdRules; these objects were selected so that they could then aid with the methods within the AlertGenerator. The general purpose of the AlertGenerator is to evaluate the incoming data, and decide whether the specific threshold has been surpassed. This is why a public boolean ‘checkWithRules’ method was created, triggering an Alert. The Alert object intentionally only holds the information of the alert (such as who, why, when and how), separating the logic from the core information. Rather, this logic is then preformed by the AlertManager task. This class then handles what occurs once an alert has been dispatched (namely routing to staff and logging the alert). This is then delegated to the MedicalStaff. This specific structure was chosen to obey by the SOLID rule of single-responsibility, and an open-closed design. Specifically, all concerns are separated, ensuring that each class has a single, well-defined responsibility. Thus, it should be relatively simple adding new threshold types or routing strategies without modifying unrelated classes.
