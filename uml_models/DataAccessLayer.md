The UML represents the two main classes, DataListener interface and DataStorage. The use of an interface in DataListener also allows for the implementation of the three subclasses: TCPDataListener, WebSocketDataListener, and FileDataListener, each of which implements the listen() method. Thus, these subclasses showcase that new data source types can be added in the future without modifying anything outside of the required data, directly satisfying the open-closed principle. Moreover, any implementation of DataListener can be substituted without affecting the rest of the algorithm flow. Once data is received, each listener passes the raw data to DataParser, which is responsible solely for parsing the raw input into a structured PatientData object. This separation ensures that the listening and parsing concerns remain independent. If the data format changes, only DataParser needs to be updated. The parsed PatientData is then passed to DataSourceAdapter, which acts as a bridge between the parsing layer and storage, handling the data and forwarding it to DataStorage through the store() method. This adapter layer ensures that DataParser remains decoupled from DataStorage directly, adding a layer of flexibility should the storage implementation change. Overall, this abides by the SOLID principles, allowing for a flexible design, thus helping with later scalability (if needed).
