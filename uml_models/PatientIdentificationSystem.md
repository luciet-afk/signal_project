The UML model has three core classes: IdentityManager, PatientIdentifier, and HospitalPatient. These classes are supported by NotFoundException for error handling, and a reference to DataStorage as discussed in the data storage UML diagram. The matching process is delegated from IdentityManager to PatientIdentifier, which then searched the DataStorage to find a corresponding HospitalPatient. If no match is found, PatientIdentifier throws a NotFoundException containing the patient ID and an error message, which IdentityManager then catches. Upon catching it, IdentityManager calls handleMismatch and logAnomaly, ensuring that any error/anomoly is both handled and recorded for correction. If a valid match is returned, IdentityManager then validates the result by checking whether the patient is currently active. The separation between PatientIdentifier and HospitalPatient was a deliberate design choice; specifically, the matching process and the patient data are kept as distinct concerns, ensuring that changes to how matching works do not affect the patient record itself. Overall, this structure abides by the single responsibility and open-closed principles, keeping each class focused on one well-defined job while remaining open to extension without modification of existing classes.
